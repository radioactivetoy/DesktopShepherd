# Code review 2 (2026-11-22)

After the new base (phases A–D), snapping, search, look options, Windows' menu and type to
jump. The automatic reviewers stopped early (usage limit), so this pass was done directly on the
riskiest areas, with targeted checks. Nothing here has been changed yet.

## What is already in good shape

- No `unwrap()`/`expect()` left outside tests; failures are logged and fall back.
- Crash and quit paths always give the desktop icons back (supervisor, panic hook, clean stop).
- Idle CPU ~0 %; hover CPU 0.6–1.4 s per 10 s (was 7.3 s); memory 88 MB after start.
- No hooks into Explorer: only out-of-process notifications and ordinary hotkeys.

## Findings

| # | Severity | Where | Problem | Fix |
|---|---|---|---|---|
| R1 | **High** (memory, stability) | `shellmenu.rs` | Windows' menu loads other programs' add-ons (7-Zip, OneDrive, Malwarebytes, Adobe, Google Drive, PowerToys… — checked) **into DeskBoxes, and they stay loaded**: +12 MB private / +35 MB working set after the first use, and any of them can crash DeskBoxes later. | Show the menu from a short-lived helper process (`deskboxes.exe --shell-menu …`) that exits after the choice; allow it to take the focus (`AllowSetForegroundWindow`). |
| R2 | Medium (UX) | icon right-click | Two steps to reach Windows' menu ("More options…"). | Right-click opens Windows' menu directly, with DeskBoxes' items ("Move to box ▸", "Remove from this box", "Open file location") inserted at its top (ids above Windows' range). The new Windows 11 menu itself is not available to other programs (no public API). |
| R3 | Low (looks) | classic menu | Windows' classic menu is light while DeskBoxes is dark. | Opt the process into dark menus (uxtheme `SetPreferredAppMode`, undocumented but widely used) — fall back silently if missing. |
| R4 | Medium (security) | `desktop.rs:135`, `:146` | `Command::new("explorer")` is looked up by name; Windows searches the app's own folder first, so an `explorer.exe` dropped next to `deskboxes.exe` would run instead. Also `/select,<path>` breaks on paths with commas. | Use `SHOpenFolderAndSelectItems` (no process, exact path), or the full `%WINDIR%\explorer.exe` path with the path quoted. |
| R5 | Low (robustness) | `desktop.rs:342`, `:776` | `prepare_box` / `round_window` find box windows **by title** ("DeskBoxes box 3"). Another program's window with that title would be registered as a box and moved in the z-order. | Use the handle the host already has (`HostSystem::hwnd(id)`); drop the title lookups. |
| R6 | Low (security, accepted) | `runloop.rs`, `desktop.rs` | Any program of the same user can post our hidden window WM_HOTKEY/WM_DISPLAYCHANGE (opens search / re-stacks boxes) or set `Local\DeskBoxes.Quit` (clean quit). Same-user programs can do worse anyway; noted, no change needed. | — |
| R7 | Low (privacy, inherent) | `icons.rs` | Loading the icon of a shortcut to `\\server\share` contacts that server (Explorer does the same). The watchdog stops hangs. | Optional setting: don't fetch icons for network paths (show a generic one). |
| R8 | Low (perf) | `app.rs:1775` | The Personalize page checks the 12 font files on disk every frame while open. | Check once at start (cache the list). |
| R9 | Low (perf) | `app.rs:242` | Monitors are still polled every 4 s although Windows now tells us at once (WM_DISPLAYCHANGE). The desktop folder is also polled every 4 s. | Drop monitor polling; watch the desktop folders with `ReadDirectoryChangesW` (STATUS idea 4). |
| R10 | Low (perf) | `desktop.rs:615` | After every desktop click the Win+D guard checks every 2 ms for 1 s (it now also wakes on focus moving to the desktop's icon list). Cheap, but 500 wake-ups per click. | Stop the guard early once the boxes have been seen above the desktop for ~300 ms. |
| R11 | Low (data) | `widgets.rs:152` | The drawing pad keeps every point forever in layout.json (pretty-printed); a busy sketch makes saves slow and the file big. | Thin out points closer than ~2 px; cap points per sketch; save compact JSON. |
| R12 | Low (memory) | `icons.rs` | Icons fetched for the search list (22 px) and the layout preview stay cached until the box icon sizes change. | Drop sizes not used by any box when the search/settings window closes. |
| R13 | Low (UX) | settings | "Check the desktop every N s (applies after restart)". | Apply live (or moot after R9). |
| R14 | Info | Explorer restart | Icon hiding is re-applied every 4 s and the hooks are global, but box z-order after a new Progman is not re-checked. | On `TaskbarCreated` (hidden window), re-stack the boxes like after a display change. |

## Suggested order

1. **R1 + R2 + R3**: right-click shows Windows' menu directly (dark, with DeskBoxes' items at
   the top), from a helper process. Fixes the biggest memory/stability issue and matches what you
   asked for.
2. **R4, R5, R14**: small robustness/security fixes.
3. **R8–R13**: small performance/data fixes.

## New feature ideas

- **Folder portal**: a box that shows the live contents of any folder (Downloads, a project).
- **Quick-hide**: double-click an empty part of the desktop to hide/show all boxes; optional
  "fade boxes when not hovered".
- **Layout snapshots**: save named layouts and switch automatically per monitor setup
  (laptop alone vs docked).
- **Rules**: auto-sort by name pattern, date (e.g. "this week") or size, not only file type.
- **Keyboard in boxes**: arrow keys between icons, Delete → Recycle Bin, F2 rename, Ctrl+A.
- **File actions**: new folder / rename inside a box; drag icons out of a box to other apps.
- **Widgets**: system monitor (CPU/RAM/disk, local only), calendar, image frame/slideshow,
  to-do list, recent files, world clock.
- **Per-item tweaks**: custom name or icon for an item without renaming the file.
- **Desktop pages**: several sets of boxes, switched with a hotkey or by scrolling the desktop.
- **Housekeeping**: rename to DesktopShepherd (exe, data folder with migration), an installer,
  release build for daily use.
